## 1. Extracted Original Proposal Requirements (`docs/Proposal.docx`)

| Category | Official Proposal Commitments (`docs/Proposal.docx`) | Distinction from Internal M02 Architecture Decisions |
| :--- | :--- | :--- |
| **Problem & Research Question** (Sec. 1) | Bridge generating code vs. proving behavioral correctness & regression safety; test whether a requirement-traceable multi-agent workflow produces more verifiably correct changes than a comparable single-agent workflow under similar task, model, and resource conditions. | Internal M02 split of `verify_existing_change` vs `generate_and_verify_change` workflow modes is an M02 engineering design supporting phased integration. |
| **Six Specialist Roles** (Sec. 5) | A1 Requirement Analyst, A2 Codebase Intelligence, A3 Change Impact, A4 Developer, A5 Testing, A6 Independent Reviewer (with fallback note: *"a four-role integrated subset will be prioritized for the first working prototype if needed"*). | Internal M02 injectable Protocols (`PatchGeneratorProvider`, `IndependentReviewerProvider`) and offline fixtures are M02 integration seams, **not** production AI agents. |
| **Multi-Agent Communication** (Sec. 5) | Deterministic central orchestrator managing shared state, handoffs, budgets, stop conditions; typed structured records (task ID, inputs, outputs, evidence refs, status, confidence/uncertainty notes) rather than untracked free-form chat. | M02 Pydantic v2 `extra="forbid"` schemas + SQLite WAL `agent_logs` + atomic CAS state transitions implement this requirement. |
| **Automated Patch Generation** (Sec. 4, 5) | A4 generates minimally scoped reviewable unified Git diff on an isolated working copy without modifying `main`. | M02 enforces immutable original snapshots, protected paths, size/file bounds, and rollback in `patch_engine.py`. |
| **Regression Verification** (Sec. 4, 5, 7) | A5 generates/runs acceptance tests and pre-existing regression tests in isolation, capturing structured pass/fail logs and regression summary. | M02 adds SHA-256 pre/post test integrity checks, baseline-vs-modified workspace mirroring, and honest granularity tracking. |
| **Bounded Repair** (Sec. 5) | Return structured test failure feedback to A4 for at most **2 repair iterations** in the MVP. | M02 adds 8 conservative eligibility rules (`RepairEligibilityEvaluator`) and duplicate-patch / no-progress stopping. |
| **Independent Review & Human Approval** (Sec. 3, 5, 9) | A6 cross-checks requirements, patch scope, tests, and limitations; reviewer disagreement or unverified behavior surfaces `"needs review"`, never silently accepted; mandatory human approval before any commit/merge; no auto-deploy. | M02 adds dual human gates (Gate 1 test review before execution + Gate 2 final decision) and unified `evaluate_approval_policy`. |
| **Explainability & Traceability** (Sec. 1, 3, 4) | Requirement-to-file-to-test trace, scoped diff, test execution logs, unresolved risk notes, audit trail. | M02 `RequirementTraceability` enforces strict explicit-mapping truthfulness (never guesses links from test names). |
| **Security & Reliability** (Sec. 6, 9) | Restrict filesystem paths; allowlisted commands; do not run arbitrary install scripts on host; isolated working copies (Docker sandbox if available); minimize logged source; never commit API keys; mitigate prompt injection; record model/version. | M02 adds `CHANGEGUARD_TRUSTED_EXECUTION_ROOTS`, `redact_secrets`, stripping raw excerpts from SQLite, and crash restart recovery. |
| **Demo & Generalization** (Exec. Summary, Sec. 7) | POS testbed (`customers.py`, `billing.py`, `inventory.py`, `payments.py`, `reports.py` + pre-existing regression tests) + an independent second small Python repository (e.g., low-stock alert) to prove non-hardcoding. | Current `sample_projects/mini_pos/` has 5 modules (`billing`, `refunds`, `reports`, `customer_service`, `dashboard`) without pre-existing `tests/`. |
| **Comparative Benchmarking** (Sec. 8, 11) | Fair Multi-Agent vs. Single-Agent baseline + Human evaluation across `>= 5` curated scenarios (POS + 2nd repo), identical model/budgets/tests; measure correctness, regression safety, patch scope, traceability, duration, tokens, API cost, robustness. Only report observed measurements. | Current engineering unit tests (145 passing) do **not** constitute comparative research evidence. |
| **Submission Deliverables** (Sec. 11) | `project/main.py`, `project/requirements.txt`, `README.md`, `docs/Proposal.docx`, `docs/Workflow.md`, `docs/PROJECT_DETAILS.md`, `project-demo.mp4` + web dashboard (React + Tailwind CSS, Sec. 6). | Additional judging/submission criteria in organizer PDFs [4]–[5] are unavailable in repo and must be verified externally. |
